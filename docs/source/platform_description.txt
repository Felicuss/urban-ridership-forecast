Краткое описание

В Едином диспетчерском центре (ЕДЦ) ГУП «Московский метрополитен» ведётся работа по созданию набора моделей краткосрочного и долгосрочного прогнозирования пассажиропотока на наземном транспорте. Участникам предстоит разработать математическую модель на базе технологий ИИ и ML, а также интерактивный веб-сервис для анализа больших данных телематики и валидаций (оплаты проезда). Решение должно позволять диспетчерам эффективно распределять подвижной состав, снижать переполнение салонов и оптимизировать затраты на эксплуатацию.

Проблематика

В настоящее время прогнозы пассажиропотока строятся на основе простейших регрессионных моделей, имеющих ограниченную точность. Телематика сама по себе не является исчерпывающим источником для прогнозирования. Отсутствует единое, масштабируемое решение, которое:

    Качественно агрегирует разрозненные массивы больших данных (валидации, расписания, геопривязка).
    Обеспечивает прогнозирование на разных горизонтах планирования с высокой точностью.
    Предоставляет удобный инструмент визуализации и выгрузки данных для принятия оперативных и стратегических решений.


Цель и целевые задачи

Цель: Разработать программное решение в виде веб-сервиса с пользовательским интерфейсом, использующее технологии ИИ/ML для прогнозирования пассажиропотока на маршрутах трамваев с привязкой к геопозиции и времени.

Целевые задачи:

    Обеспечить получение прогноза на три горизонта: краткосрочный (день, с разбиением по часам на предикты), среднесрочный (месяц), долгосрочный (год - опциональный сценарий).
    Реализовать агрегацию прогноза по заданным параметрам: маршрут, остановка/участок, интервал времени.
    Создать пайплайн приёма, нормализации и геопривязки исторических данных валидаций по расписанию и остановкам.


Образ решения

Контейнеризированный программный продукт (веб-сервис: Backend + Frontend), развертываемый через Docker. Сервис предоставляет REST/HTTP API для получения прогнозов, интерактивный дашборд с визуализацией динамики загрузки на карте Москвы в реальном времени, а также функционал экспорта данных в табличном виде.

Функциональные требования

    Гибкое прогнозирование: Построение предиктивных моделей на горизонты 1 день, 1 месяц, 1 год.
    Детализированная агрегация: Фильтрация и агрегация прогноза по конкретным маршрутам, отдельным остановкам и выбранным временным интервалам.
    Интерактивный дашборд: Визуализация динамики изменения пассажиропотока по времени по маршруту в заданных точках (остановки) на карте Москвы.
    Экспорт данных: Возможность выгрузки результатов прогноза в форматах CSV и/или XLSX.
    Учет внешних факторов: Возможность учета времени суток, дня недели, сезонности и погодных условий (при наличии соответствующих данных).


Требования к архитектуре и рекомендации по технологическому стеку

Рекомендуемый прикладной стек:

    Backend: Java 17+ (рекомендуется Java 21 LTS), Spring Boot 4.0+ (рекомендуется 4.1.x), Netty (реактивный стек / Spring WebFlux для высокой пропускной способности).
    Frontend: React 19+, TypeScript 5.x+.
    ML-контур: Python (scikit-learn / LightGBM / PyTorch) с поставкой артефактов модели и/или инференс в JVM через ONNX Runtime / DJL.
    Инфраструктура: Docker, Docker Compose.
    Рекомендуемые компоненты: СУБД / хранилище истории (PostgreSQL, ClickHouse или файловое columnar-хранилище), библиотека карт для UI (MapLibre / Leaflet / Yandex Maps API).
