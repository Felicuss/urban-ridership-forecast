# Агент: исчерпание шести обращений к модели

Проверено 27.09.2026 на локальном стенде Podman с Ollama Cloud `gpt-oss:120b`.
Исходный код — `9e12a61`; исправления пока в рабочем дереве и установлены локально.

## Как возникал отказ

В диагностическом повторе исходного Java-цикла на настоящих модели и MCP вопрос
«Где на этой неделе рейсы переполнены?» с датой экрана 16.11.2025 привёл к такой последовательности:

| Обращение | Что запросила модель | Результат |
|---|---|---|
| 1 | `forecast`, уровень route, без id | Ошибка обязательного параметра |
| 2 | `forecast`, маршрут 1 | Данные получены |
| 3 | `forecast`, маршрут 5 | Данные получены |
| 4 | `forecast`, маршрут 7 | Данные получены |
| 5 | `forecast`, маршрут 11 | Данные получены |
| 6 | `forecast`, маршрут 12, даты `...` | Ошибка даты, затем лимит цикла |

Модель выбрала период 11–17 ноября и утренние часы 7–10. Это также не соответствовало запросу всей
календарной недели. Другой запуск завершился раньше, но сделал вывод о переполнении по посадкам
на маршрут в один час. Поведение модели непостоянно; это не восстановление истории пользовательского чата.

Лимит в коде считал обращения к модели, а не отдельные инструменты. После шестого ответа с вызовом
инструмента его выполняли, но уже не возвращали результат модели. Вместо итога выдавалась заглушка.
Для сравнения всех маршрутов за неделю инструментов не хватало: модель перебирала маршруты сама.

## Исправление

- Сохранён предел шести обращений: пять раундов сбора данных и одно завершение. Модель видит бюджет.
- Финальный запрос содержит исходный вопрос и собранные результаты обычным текстом. Из него удалены
  история вызовов и инструкции выбирать инструменты; выставлен `tool_choice: none`.
  В диагностике одного `tool_choice: none` оказалось недостаточно: Ollama вернула новый вызов.
- Точные повторы используют результат текущего хода, включая команды интерфейсу. Раунд только
  из повторов приводит к раннему завершению. Неполный результат должен быть обозначен явно.
- Добавлен `weekly_load`: неделя понедельник–воскресенье определяется кодом, проверяются все
  10 маршрутов и 24 часа каждого дня. Формула совпадает с фронтом: посадки за час × интервал / 120.
  Порог 185 — оценка риска по посадкам на рейс, не измерение заполненности вагона. Пропуски расписания
  указаны отдельно; границы периода обрезаются только по доступной шкале и помечаются как неполная неделя.
- Результат включает полный список маршрутов с риском и их число. Результаты предыдущего формата
  Redis отделены версией ключей кэша. В журнале — id хода, номер обращения, имя инструмента и повторы,
  без ключей и текстов диалога.

## Что проверено

- API и MCP собраны, локальные контейнеры обновлены, readiness API — UP.
- На окончательном исправлении вопрос с датами экрана 16.11 и 19.11 прошёл через API за 3,58 и 3,05 с.
  В обоих случаях журнал API подтверждает два обращения к модели и один `weekly_load`.
- Полная сводка инструмента занимает 3191 символ и помещается в лимит 6000.
- Записанный сбойный диалог после первых пяти обращений отдельно продолжен новым финальным запросом:
  модель дала текст без вызовов и указала, что данных о вместимости и рейсах недостаточно.
- Добавлены регрессионные тесты завершения, повторов, календарной недели, выходных и пропусков расписания.
  Автотесты и CI не запускались по ограничению пользователя. Сборка и `git diff --check` прошли.

Локальный nginx после пересоздания настроен на DNS Podman. Это правка текущего контейнера;
при следующем пересоздании из исходного образа её потребуется повторить.
