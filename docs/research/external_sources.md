# Внешние источники: календарь, каникулы, погода, трафик, световой день

Задача: почасовые посадки трамваев Москвы, история 2025-01-01..2025-10-31, прогноз 2025-11-01..2025-12-31. Все запросы ниже выполнены 2026-09-25. Воспроизводимая выгрузка: `analysis/s01_fetch_weather.py` и `analysis/s08_fetch_external.py`, результаты лежат в `external/`.

Главное, что меняет модель в окне прогноза:

| Дата | День | Статус | Откуда |
|---|---|---|---|
| 2025-11-01 | Сб | рабочий, сокращённый на 1 час | перенос выходного на 03.11 |
| 2025-11-02 | Вс | выходной | обычный |
| 2025-11-03 | Пн | выходной | перенос с 01.11 |
| 2025-11-04 | Вт | нерабочий праздник | День народного единства |
| 2025-12-30 | Вт | обычный полный рабочий день | 31.12 не праздник, а перенесённый выходной, поэтому 30.12 не сокращается |
| 2025-12-31 | Ср | выходной | перенос с воскресенья 05.01 |

Рабочая суббота 01.11 - единственная в 2025 году, и в истории (январь-октябрь) таких дней нет ни одного. Выучить её эффект из train нельзя, её придётся задавать правилом (например, профиль будня или среднее будня и субботы). Проверено: в регрессии ниже признак `work_weekend` на истории тождественно равен нулю.

### Машиночитаемые источники

**isdayoff.ru.** Проверено, работает, данные совпадают с постановлением. Документация: https://www.isdayoff.ru/docs/

```bash
# весь год, 365 символов: 0 рабочий, 1 нерабочий, 2 сокращённый (pre=1)
curl "https://isdayoff.ru/api/getdata?year=2025&cc=ru&pre=1"
# окно прогноза
curl "https://isdayoff.ru/api/getdata?date1=20251101&date2=20251231&cc=ru&pre=1"
# -> 2111000110000011000001100000110000011000001100000110000011001
# с holiday=1 официальный праздник получает код 8
curl "https://isdayoff.ru/api/getdata?year=2025&month=11&cc=ru&pre=1&holiday=1"
# -> 211800011000001100000110000011
# один день
curl "https://isdayoff.ru/20251101?cc=ru&pre=1"   # -> 2
curl "https://isdayoff.ru/20251231?cc=ru&pre=1"   # -> 1
curl "https://isdayoff.ru/20251230?cc=ru&pre=1"   # -> 0
```

Раскодированный ответ за год даёт ровно список выше (247/118). Ограничение из документации: запрос произвольного диапазона не длиннее 366 дней. Коды ошибок: 100 (неверная дата или страна), 101 (нет данных), 199 (ошибка сервиса). Лицензия на данные не указана, у репозитория https://github.com/isdayoff/calendars лицензии нет. Бесплатно, ключ не нужен.

**xmlcalendar.ru.** Проверено, работает. Отдаёт и переносы явно, что удобно для отчёта.

```bash
curl "https://xmlcalendar.ru/data/ru/2025/calendar.json"
curl "https://xmlcalendar.ru/data/ru/2025/calendar.xml"
# зеркало на GitHub (HTTP 200):
curl "https://raw.githubusercontent.com/xmlcalendar/data/master/ru/2025/calendar.xml"
```

В JSON: `"transitions": [{"from":"01.04","to":"05.02"}, {"from":"02.23","to":"05.08"}, {"from":"03.08","to":"06.13"}, {"from":"11.01","to":"11.03"}, {"from":"01.05","to":"12.31"}]`, `"statistic": {"workdays": 247, "holidays": 118, "hours40": 1972}`. В днях: `*` сокращённый, `+` перенесённый выходной. В XML `t="2"` сокращённый, `f="01.04"` откуда перенесён. У репозитория github.com/xmlcalendar/data лицензии нет.

**Python-пакет holidays.** Последняя версия на PyPI: 0.105 (релиз 2026-09-21, лицензия MIT, https://github.com/vacanza/holidays), в индексе уже лежит 0.106.dev. Проверено на 0.105:

```python
# uv run --with holidays==0.105 python
import datetime as dt, holidays
ru = holidays.country_holidays("RU", years=2025, language="ru")
# 2025-05-02 Выходной (перенесено с 04.01.2025)
# 2025-05-08 Выходной (перенесено с 23.02.2025)
# 2025-06-13 Выходной (перенесено с 08.03.2025)
# 2025-11-03 Выходной (перенесено с 01.11.2025)
# 2025-12-31 Выходной (перенесено с 05.01.2025)
ru.is_working_day(dt.date(2025, 11, 1))   # True, рабочая суббота учтена
ru.weekend_workdays                        # {2025-11-01}
sum(ru.is_working_day(dt.date(2025,1,1)+dt.timedelta(i)) for i in range(365))  # 247
```

Переносы отдаёт корректно, рабочую субботу знает. Сокращённых дней в пакете нет: для RU поддерживается только категория `public`, запрос `categories=("workday",)` падает с `Category is not supported: workday.` Сокращённые дни берём из isdayoff (`pre=1`) или xmlcalendar.

Рекомендация: в коде использовать holidays 0.105 как основной офлайн-источник (без сети, MIT) и isdayoff как ссылку «рабочий способ получения» для жюри, флаг сокращённого дня брать из isdayoff/xmlcalendar.

## 3. Почасовая погода

### Open-Meteo Historical Weather API (рекомендую как основной)

Запрос из задания выполнен, HTTP 200:

```bash
curl "https://archive-api.open-meteo.com/v1/archive?latitude=55.7558&longitude=37.6173&start_date=2025-11-01&end_date=2025-11-02&hourly=temperature_2m,precipitation,rain,snowfall,snow_depth,weather_code,wind_speed_10m,apparent_temperature&timezone=Europe%2FMoscow"
```

Ответ: ближайшая ячейка 55.782074, 37.576374, высота 140 м, `timezone: Europe/Moscow`, `utc_offset_seconds: 10800`, 48 часов. Первые часы 2025-11-01: temperature_2m 5.1, 5.1, 5.2 °C, precipitation 0.00, weather_code 3, wind_speed_10m 9.2 км/ч, apparent_temperature 2.4 °C. Единицы: snowfall в см, snow_depth в м, ветер в км/ч.

Полный год тоже отдаётся одним запросом (`start_date=2025-01-01&end_date=2025-12-31`): 8760 часов, пропусков ноль по temperature_2m, precipitation, snowfall, snow_depth, weather_code. Суммы по центру Москвы: ноябрь 68.9 мм и средняя 3.2 °C, декабрь 42.5 мм и -1.8 °C. Снежный покров появляется с 2025-11-15, самый сильный снегопад 2025-12-26 (6.5 см за сутки).

Модели через параметр `models=`: `best_match` для Москвы фактически берёт ECMWF IFS 9 км (сетка и значения совпали с `ecmwf_ifs`), `era5` - 0.25° (ячейка 55.75, 37.5), `era5_land` - 0.1°, но осадки в нём пустые (null за весь период), `era5_seamless` тоже доступен.

Лимиты и лицензия (https://open-meteo.com/en/terms): бесплатно только для некоммерческого использования, 600 вызовов в минуту, 5000 в час, 10 000 в день, 300 000 в месяц; данные под CC BY 4.0, нужна атрибуция. Хакатон подходит под некоммерческое использование, для продукта нужен платный тариф.

### Проверка точности против станции Москва-ВДНХ (27612)

Сравнил Open-Meteo с наблюдениями за 2025-11-01..2025-12-31:

| Источник Open-Meteo | Ячейка | MAE T, °C (488 срочных наблюдений) | Смещение, °C |
|---|---|---|---|
| центр, best_match | 55.782, 37.576 | 0.71 | -0.61 |
| ВДНХ, best_match / ecmwf_ifs | 55.852, 37.653 | 0.77 | -0.69 |
| ВДНХ, era5 | 55.75, 37.50 | 0.81 | -0.76 |
| ВДНХ, era5_land | 55.80, 37.60 | 1.11 | -0.96 |

По суткам (метеосутки 18-18 UTC, как у pogodaiklimat.ru, 60 дней): корреляция средней суточной температуры 0.992, MAE 0.68 °C; корреляция суточных осадков 0.95; совпадение «был день с осадками ≥1 мм или нет» в 90% дней. По месяцам станция: ноябрь 3.8 °C и 74 мм, декабрь -1.1 °C и 36 мм; Open-Meteo: 3.2 °C и 68.9 мм, -1.8 °C и 42.5 мм.

Модель стабильно холоднее станции на 0.6-0.8 °C (городской остров тепла, станция внутри города). Слабые осадки ниже 1 мм реанализ пропускает: ночью 2025-11-01 станция записала ливневой дождь (R=1 мм в срок 03 UTC), в Open-Meteo там 0.0. Для прогноза спроса по всему городу это приемлемо.

Какой источник точнее: в точке станции, конечно, сама станция. Но её данные только раз в 3 часа, осадки за 6-12 часов, и их нужно парсить. ERA5 0.25° грубее IFS 9 км, это видно по MAE. Для модели беру Open-Meteo `best_match` по центру: без пропусков, почасовой, один и тот же источник для истории и окна прогноза, а станцию использую как проверку и для явлений (гололёд, метель).

### Meteostat (не рекомендую как источник осадков для Москвы 2025)

Это только «сейчас», для 2025 года бесполезно. В Wayback Machine за 2025 год три снимка этого URL (`https://web.archive.org/cdx/search/cdx?url=export.yandex.ru/bar/reginfo.xml*&from=2025&to=2025`), страница пробок yandex.ru/maps/213/moscow/probki в архиве только с кодом 302. Старый сторонний архив smotra.ru/probki работал лишь в 2010 году. На GitHub нашлись только информеры текущего балла, архивов нет.

**TomTom Traffic Index.** Москвы нет: https://www.tomtom.com/traffic-index/moscow-traffic/ отдаёт 404. Коммерсантъ 21.01.2026 (https://www.kommersant.ru/doc/8364004): «Москва и другие российские города в рейтинг TomTom не попадают с 2022 года». Там же годовые цифры ЦОДД: 9 баллов и выше в 2025 году было всего 7 раз (на 56% меньше, чем в 2024), до 2.79 млн автомобилей в сутки.

**data.mos.ru.** API требует ключ: `curl "https://apidata.mos.ru/v1/datasets?$top=2"` возвращает 401 «Необходимо указать api_key». Временных рядов загруженности или скорости среди дорожных наборов не нашёл, там статические объекты (табло на УДС, «Безопасные улицы», платные парковки). Полный каталог без ключа не перебирал, это не до конца проверено.

**Дептранс/ЦОДД в Telegram.** Реальный способ получить хоть какой-то ряд за ноябрь-декабрь 2025. Канал @DtOperativno публикует «N баллов по данным ЦОДД», веб-превью без авторизации пролистывается назад параметром `before`:

```bash
curl -A "Mozilla/5.0" "https://t.me/s/DtOperativno?before=24000"
# 2025-12-10T05:31:36Z ... на дорогах 4 балла по данным ЦОДД
# 2025-12-10T09:24:56Z На дорогах - 4 балла по данным ЦОДД
```

Номера сообщений: около 22000 соответствует июлю 2025, около 24000 - 9-10 декабря 2025. Данные редкие и привязаны к событиям (на странице из 20 постов балл есть в 2). Из них можно собрать признак «максимальный объявленный балл за день». Канал @CODDmos в веб-превью заканчивается февралём 2026.

**Новости об экстремальных днях** в окне прогноза: 11.12.2025 в 19:10 пробки 10 баллов, впервые с 19.12.2024, причины по Дептрансу - погода, локальные перекрытия, ремонт (РИА https://ria.ru/20251211/moskva-2061505277.html , РБК https://www.rbc.ru/society/11/12/2025/693ae9839a79476666be9d4c); 24.12.2025 перекрытия в центре, 9 баллов в заголовке msk1.ru (https://msk1.ru/text/transport/2025/12/24/76187993/).

Вывод: честно заявлять трафик как внешний источник можно только в виде событийных флагов (Telegram-канал плюс новости) или косвенно через погоду и календарь. Если нужен именно почасовой балл, остаётся собирать `reginfo.xml` раз в 10-15 минут начиная с сегодняшнего дня, для 2025 года это не поможет.

## 5. Восход, закат, световой день

astral 3.2 (последняя на PyPI, релиз 2022-11-05, Apache-2.0). Проверено:

```python
# uv run --with astral==3.2 python
import datetime as dt
from zoneinfo import ZoneInfo
from astral import LocationInfo
from astral.sun import sun
loc = LocationInfo("Moscow", "Russia", "Europe/Moscow", 55.7558, 37.6173)
s = sun(loc.observer, date=dt.date(2025, 12, 21), tzinfo=ZoneInfo("Europe/Moscow"))
# sunrise 08:58, sunset 15:57, dawn 08:10, dusk 16:45, день 6 ч 59 мин
```

Контрольные даты: 2025-11-01 восход 07:36, закат 16:49 (9 ч 13 мин); 2025-12-31 08:59 и 16:05; 2025-06-21 03:45 и 21:17 (17 ч 33 мин). Сверка с Open-Meteo (`daily=sunrise,sunset,daylight_duration` в том же archive API): расхождение восхода за ноябрь-декабрь не больше 69 секунд, это округление до минуты у Open-Meteo. Можно обойтись без astral и брать световой день из того же запроса погоды.

## 6. Проверка эффекта на данных проекта

Чтобы было что показать по критерию «подтверждён эффект», прогнал быструю регрессию на суточных суммах `dataset/labels/labels_day_train.csv` + `labels_day_test.csv` (2025-01-01..2025-10-31, 304 дня, 9 маршрутов в разметке). Модель: log(посадки за сутки) ~ день недели + месяц + календарь + погода Open-Meteo за 06-21 ч, робастные ошибки HC1. Это быстрая проверка агента-исследователя; воспроизводимая версия с HAC-ошибками лежит в `analysis/s05_weather_effect.py` и `analysis/s09_external_factors.py`, её результаты в `docs/analysis/README.md`.

| Признак | Эффект | p-value |
|---|---|---|
| нерабочий день в будни | -52.6% | <0.0001 |
| сокращённый предпраздничный день | +2.5% | 0.009 |
| школьные каникулы | -3.2% | 0.058 |
| осадки, на 1 мм за 06-21 ч | -0.95% | <0.0001 |
| снегопад, на 1 см | -2.1% | 0.37 |
| температура (линейная и квадрат) | не значима при месячных эффектах | 0.68 / 0.18 |

R²: только день недели и месяц 0.727, плюс календарь 0.937, плюс погода 0.949. Календарь даёт основной прирост, осадки значимы, температура на суточном уровне съедается месячными эффектами. Почасовой эффект осадков (в часы пик он, скорее всего, сильнее) я не проверял.
