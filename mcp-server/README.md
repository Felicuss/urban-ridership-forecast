# MCP-сервер для агента диспетчера

Отдельный микросервис на Python 3.14 и официальном SDK `mcp` 2.2.0. Агент диспетчера на Java (`backend/`, модель через Ollama Cloud) получает от него 14 инструментов: 11 читают данные из REST API сервиса прогноза, 3 управляют интерфейсом. Подключить можно и любой другой MCP-клиент. Сервис на Java не меняется: MCP-сервер ходит в `/api/v1` как обычный клиент.

## Запуск

```
cd mcp-server
uv sync
TRAM_API_URL=http://localhost:8080/api/v1 uv run tram-mcp      # http://127.0.0.1:8765/mcp, Streamable HTTP
uv run pytest                                                   # 6 тестов без сети
uv run python scripts/smoke.py http://127.0.0.1:8765/mcp        # вызовы по сети к живому API
```

В Docker поднимается вместе со всем стеком: `docker compose up -d --build`, адрес `http://localhost:8765/mcp`.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `TRAM_API_URL` | `http://localhost:8080/api/v1` | куда сервер ходит за данными |
| `TRAM_PUBLIC_URL` | как `TRAM_API_URL` | адрес API для ссылок на выгрузку, которые увидит пользователь |
| `MCP_HOST`, `MCP_PORT` | `127.0.0.1`, `8765` | где слушать; в контейнере `0.0.0.0` |

## Инструменты

| Инструмент | Что делает |
|---|---|
| `model_info` | версия модели, точность на проверке организаторов, горизонт, границы данных, область применимости |
| `list_routes`, `find_stops` | маршруты; остановки по части названия, можно в пределах маршрута |
| `forecast` | посадки по сети, маршруту, остановке или участку за период с шагом час, сутки, месяц или горизонт; ответ сжат до итога, пика, источников и 400 точек |
| `network_load` | посадки всех маршрутов за сутки и в час, 5 самых загруженных остановок |
| `scenario`, `coefficients_catalog` | прогноз «что если» по ползункам и событиям с разницей к базе; список ползунков |
| `calendar` | тип дня, праздник и источник данных за период до 120 дней |
| `export_link` | ссылка на CSV или XLSX |
| `transport_news` | сбои трамваев из канала Дептранса: маршрут, начало и конец, причина, место, ссылка, учтён ли сбой в прогнозе |
| `news_events` | события сценария, если такой же сбой случится в выбранный день; их можно сразу передать в `scenario` |
| `ui_show`, `ui_layers`, `ui_ride` | команды интерфейсу: дата и час, маршрут или остановка, вид карты, вкладка (в том числе «Смена»), слои, скрытые маршруты, поездка трамвая |

Команды интерфейсу ничего не делают сами. Они проверяют параметры (дата в пределах данных, маршрут существует, слой известен) и возвращают `{"ui": {...}}`. Агент передаёт это фронту, фронт применяет к своему состоянию. Так модель не может открыть несуществующий маршрут или 2027 год.

## Ограничения для модели

Инструкции сервера задают рамки: только посадки на 10 трамвайных маршрутах с января 2025 по октябрь 2026, числа только из инструментов, источник (факт, прогноз, оценка) называется явно, при нехватке даты, маршрута или периода модель переспрашивает. Неверные параметры отсекаются до запроса к API. Ошибки API (RFC 9457) доходят до модели текстом `detail`, например «маршрута 99 нет в сервисе, доступны [1, 5, 7, …]», и модель может объяснить пользователю, что не так.
